# Phase 3 design addendum — hazard model, extreme-rain corrector, baselines, case studies (stage 2)

Parent: `docs/superpowers/specs/2026-09-30-aetherguard-design.md` section 7, `docs/phase1-design.md` (D1–D7), `docs/phase2-design.md`. No git. Workflow per task: builder (Sonnet) test-first, then independent review for risky modules, controller adjudicates.

## What the real data allows (decisions driven by measured facts)
- Labels: 919 day-exact positive cell-days (train 591, validation 233, test_2018 85, test_sparse 10) plus the 2023 window test (176 events, 24 cells). Statistical power on test_2018 is low (85 cell-days, 36 in the Ghats). Every headline number carries a bootstrap CI (resampling EVENTS/cell-days, and separately blocks of days for negatives) and the report states plainly when the CI is too wide to separate models.
- Rain for features: IMD gauge grid (India, native 0.25°, nearest cell) is primary; CHIRPS (0.05°, aligned to the IMD day by D5) is the independent second source and the only source for Nepal/Bhutan cells and cells off the IMD grid. `rain_source` recorded per row.
- **Hourly peak intensity (spec 7.1) is dropped from the gridded model.** Per-cell hourly data cannot be ingested (Open-Meteo quota), so only the two case-study points get an ERA5/IFS hourly series. Reported as a spec deviation in the final report. Daily accumulations 1/3/5/7/14/30 d, 1-day fraction of the 3-day total and rain anomaly vs the cell's own training-period climatology stand in for intensity.
- Soil wetness: POWER/MERRA-2 GWETTOP/GWETROOT (coarse, ~0.5° × 0.625°); used as antecedent-wetness features (level, 3/7-day change).
- Static: slope/relief/curvature from Copernicus DEM (Task 4), aspect if Task 4 provides it; WorldCover/SoilGrids/roads are optional stretch (only added if the ablation shows gain and ingest cost is small). Lithology is not available in an open verified source: listed as a limitation.
- Integrity features (trust-weighted station rain, fraction of trusted stations within 100 km, station-vs-grid discrepancy) come from the Phase 2b engine outputs, built for the historical GHCN stations only; cells without a station within 100 km get explicit NaN (LightGBM native missing handling) plus `n_stations_100km = 0`. Because only 140 stations exist, this feature group is expected to be weak; the ablation will say so honestly.

## Model decisions
- **Unit**: (0.05° cell, date), positives from the frozen splits, negatives per D3 (10:1 per split), sampled once by the Task 5 sampler (seeded), never resampled after looking at results.
- **Features** (groups, each ablatable): `rain` (accumulations, anomaly, 1-day share), `disagree` (IMD vs CHIRPS-aligned: difference and ratio at 1/3/7 d), `wetness`, `static`, `integrity`, `region` flag is NOT a feature (leave-region-out evaluation must be honest).
- **Model**: LightGBM binary classifier, monotone constraints +1 on the rain accumulations (1–30 d) and on slope and relief, 0 elsewhere; class balance handled by the fixed 10:1 sampling, with the operating prevalence correction applied in calibration (below) so probabilities refer to the TRUE base rate, estimated from the number of cell-days per region-year (documented, with its uncertainty).
- **Hyper-parameters**: small fixed grid (num_leaves, min_data_in_leaf, feature_fraction, learning_rate with early stopping) chosen on validation only; the choice and every candidate's validation score are stored.
- **Calibration**: isotonic on validation predictions (train-period fit, validation-period calibration), reliability table and ECE reported on test_2018 and the region-held-out sets.
- **Uncertainty**: bootstrap ensemble of 20 LightGBM models (resampled training rows, seeds fixed): interval = 10th–90th percentile of calibrated probabilities; also stored: ensemble std. Reported: coverage is NOT claimed for events (too few); the interval is used in the alert engine (upper bound drives Watch escalation).
- **Explanations**: LightGBM `pred_contrib=True` (built-in SHAP), top-5 contributions per alert.
- **Baselines** (same rows, same splits): (1) intensity-duration / antecedent-rain threshold rule with thresholds fitted on train positives (published-style form `I = a * D^-b`, fitted by quantile regression at the 10th percentile of positive-event rain), (2) LHASA-style susceptibility × rain rule (susceptibility = slope-based class, rain trigger = 95th percentile of the cell-climatology of 3-day rain), (3) logistic regression on standardised rain + slope features.
- **Evaluation**: PR-AUC (with prevalence-correct reporting: PR-AUC on the sampled set is only comparable across models, so also report detection rate at fixed false-alarm rate per cell-day computed against the FULL region-day universe for test_2018), detection rate at fixed false-alarm burden (e.g. alerts per 1000 cell-days), calibration error, and warning lead time defined on the alert engine output (Phase 4); all with CIs. Leave-region-out: train Himalaya → test Ghats and the reverse, reported separately.
- **Window-level test** (2023 India inventory): a cell is detected if an alert of Watch or higher occurs in it or its 8 neighbours on any day of 2023-06-16..2023-07-31; false alarms are an upper bound (inventory partial).
- **Ablations**: remove each feature group in turn (integrity, disagree, wetness, static), and the corrector; report the change with CIs.

## Extreme-rain corrector
- Target: gauge daily rain at GHCN stations (IMD-day basis). Predictors: aligned CHIRPS value, IMD grid value at the station cell (only where the gauge itself is not an input to the grid — IMD gauge grids ingest many of the same gauges, so the IMD predictor is reported as a LEAKAGE-RISK variant and the headline corrector excludes it), POWER wetness, slope/relief at the cell, elevation, day-of-year, coarse monsoon-wind exposure proxy (upslope wind component only if a wind source is ingested; otherwise dropped and listed).
- Model: LightGBM quantile regression (alpha 0.5, 0.9, 0.99) and a binary exceedance classifier for P(gauge ≥ local 99th percentile of wet days of the training years).
- Evaluation on held-out STATIONS (the Phase 2 station split): pinball loss vs the raw CHIRPS value, exceedance PR-AUC and recall at fixed false-flag rate, bias on the top 1% of days, with station-bootstrap CIs.
- Honesty rule: the spec's known risk (few lowland gauges cannot close a Wayanad-scale gap) is tested directly on the Wayanad case-study day; if the corrector does not raise the estimate, the report says so and the alert engine widens uncertainty instead.

## Protocol v2 (controller ruling, 2026-10-02, after the v1 run)
v1 (`reports/phase3_hazard_report_v1.md`) used the 2016-17 validation split for hyper-parameter selection (48 candidates), early stopping on a noisy false-alarm metric, isotonic calibration AND the 90%-recall threshold. That re-use made the threshold optimistic: test_2018 recall at the validation threshold was 78.8% (target 90%), calibration over-predicted by 36%, and the model tied all baselines on test. `stat_elev_mean` was the top feature (17% gain), a probable location/inventory-bias proxy.
v2, decided before any further look at test_2018:
- Development period 2007-2017 (train + validation splits pooled as rows, never test_2018). Year-blocked cross-validation (folds = contiguous year blocks, e.g. 2007-08, 2009-10, 2011-12, 2013-14, 2015, 2016, 2017) for ALL choices: hyper-parameters (small, regularised grid), number of trees (median of fold-optimal counts), feature groups (incl. dropping elevation-like static columns, adding `integ_` and `corr_` when available).
- Calibration and thresholds from the pooled out-of-fold scores (universe weights per year), recall-first margin: the operating threshold is the highest one whose bootstrap 5th-percentile out-of-fold recall is >= 90%.
- Final model refit on all development rows with the chosen settings; baselines get the identical treatment (thresholds from their own out-of-fold scores over 2007-2017).
- test_2018 is evaluated exactly once with everything frozen; v1 numbers stay in the report as disclosed history (the protocol change was partly prompted by the v1 test result — stated plainly).

## Finding: CHIRPS daily artifact at Wayanad (controller check, 2026-10-03)
Raw CHIRPS v2.0 p05 files (not our store) for the Wayanad 3x3 pixel block read exactly 0.0 on 2024-07-26, 07-28, 07-30 and repeat identical non-zero values on alternate days (e.g. centre pixel 49.7 mm on 07-29 and 07-31; neighbours 61.6/45.4/47.5 repeated). Our cropped store reproduces the source faithfully. Interpretation: an artifact of CHIRPS's daily disaggregation of pentadal totals, not a processing bug. Consequence: on the Wayanad event day CHIRPS-UTC = 0 mm while IMD = 179 mm, the nearest trusted gauge (45 km) = 154.9 mm and ERA5 (IMD-day exact) = 66.9 mm. Reported as a limitation of CHIRPS as a daily trigger source; it is the motivating case for the IMD-vs-CHIRPS disagreement features and the alert engine's max-of-sources escalation rule.

## Finding: post-evaluation bug fix and disclosed rerun (2026-10-03)
After the single frozen test_2018 evaluation, controller review found a sign bug in the POINT value of the paired recall difference at fixed thresholds (`recall_model_minus_baseline`, `hazard/evaluate.py::_paired_fixed`): the bootstrap interval was model minus baseline but the point value was baseline minus model (e.g. reported +0.025 vs intensity-duration while model recall 0.850 < baseline 0.875). Fixed, with a regression test whose two scorers have different recalls (the old test had equal recalls, so it could not catch it). The evaluation was re-run once with `--rerun` (logged in `data/processed/hazard/model/TEST_EVALUATION.json`, runs at 11:54Z and 16:23Z); the model freeze verified before and after; nothing else changed: recall at Watch 0.850 [0.775, 0.925], FA share 0.214, FA differences and all verdicts identical. Corrected recall differences at the frozen Watch thresholds: model minus intensity-duration -0.025 [-0.088, 0.038], minus LHASA-style -0.038 [-0.125, 0.038], minus logistic -0.013 [-0.063, 0.038] — all within noise.
